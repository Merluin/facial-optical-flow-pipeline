Overview & Goals

This pipeline processes videos of facial expressions to extract optical flow vectors that capture the motion and deformation of facial muscles during emotional expression. The primary goals are:

  • Face Standardization: Align all faces to a canonical reference frame (center, size, rotation)
  • Expression Apex Detection: Identify the frame of maximum emotional intensity using motion cues
  • Temporal Segmentation: Extract a focused window around the apex (onset → peak → decay)
  • Motion Quantification: Compute dense optical flow to measure pixel-level facial deformation
  • Data Export: Save flow vectors in compact format (NPZ) with visualization (GIF)

Pipeline Architecture

Video File ↓ (Load frames) Frame Sequence (N frames) ↓ (Detect face) Face Bounding Boxes (per frame) ↓ (Smooth boxes) Smoothed Bboxes (temporal stability) ↓ (Align & crop) Standardized Face Frames (256×256, centered) ↓ (Register to frame 0) Registered Face Frames (rigid motion removed) ↓ (Compute motion) Motion Signal (per-frame magnitude) ↓ (Find apex) Apex Frame Index ↓ (Segment: apex-40 to apex+5) Segmented Frames (45 frames total) ↓ (Apply mask, compute OF) Optical Flow Arrays (44 flow maps) ↓ ├→ NPZ File (flow + metadata) └→ GIF Animation (visualization)

Step 1: Video Loading & Frame Extraction

1Load Video Frames

Read all frames from the video file using OpenCV's cv2.VideoCapture.

Process:

  • Open video file with cv2.VideoCapture(video_path)
  • Extract FPS from video metadata
  • Read all frames sequentially into memory (BGR format)
  • Release video file handle

Output:

  • frames_raw: List of N numpy arrays, each shape (H, W, 3), dtype uint8
  • fps: Frames per second (float)

Step 2: Face Detection with Haar Cascades

2Detect Faces Frame-by-Frame

Use OpenCV's pre-trained Haar cascade classifier to detect frontal faces in each frame.

Algorithm:

  • Convert each frame to grayscale
  • Run cascadeClassifier.detectMultiScale(gray, scaleFactor=1.1, minNeighbors=5, minSize=(50,50))
  • If multiple faces detected, select the largest by area
  • If no face detected, carry forward the previous frame's bbox (temporal continuity)

Output:

  • bboxes: List of (x, y, w, h) tuples, one per frame
  • x, y: Top-left corner of bounding box
  • w, h: Width and height of box
⚠️ Limitation: Haar cascades work best on frontal faces with good lighting. Profile views or extreme angles may fail. Use PAD_FACTOR to adjust detection sensitivity.

Step 3: Face Standardization (Alignment & Cropping)

3Standardize Face Position & Size

Transform each face to a canonical reference: centered, aligned, and cropped to a fixed square size.

Process for Each Frame:

A) Eye Detection & Rotation Alignment

left_eye = (x + 0.25w, y + 0.35h) right_eye = (x + 0.75w, y + 0.35h) angle = atan2(right_eye.y - left_eye.y, right_eye.x - left_eye.x) × 180/π

Estimate eye positions from the bbox geometry. Compute the angle between eyes. Rotate the frame so the eyes are perfectly horizontal (angle = 0°).

B) Padded Bounding Box

bbox_rotated = rotate_points(bbox, angle, frame_center) padding = PAD_FACTOR × max(width, height) bbox_padded = bbox_rotated + padding (all sides)

After rotation, recompute the bbox in rotated space. Add symmetric padding (default PAD_FACTOR=0.35) to include neck, some hair. Adjust for better face isolation.

C) Square Crop

side = max(bbox_padded.width, bbox_padded.height) x1 = center_x - side/2 y1 = center_y - side/2 crop_region = frame[y1:y1+side, x1:x1+side]

Force a square crop (important for symmetric optical flow). Center the crop and ensure it stays within image bounds.

D) Resize

output = cv2.resize(crop_region, (CROP_SIZE, CROP_SIZE))

Resize the cropped region to a fixed size (default 256×256). Use bilinear interpolation.

Output:

  • std_frames: List of N arrays, each shape (256, 256, 3), dtype uint8, BGR
  • All faces centered, rotation-aligned, same size
💡 Tip: If you see shoulders/hair in the OF visualization, reduce PAD_FACTOR to crop tighter. If the face is cut off, increase it.

Step 4: Bounding Box Smoothing & Affine Registration

4Stabilize Face Tracking & Remove Rigid Motion

Two-stage stabilization to reduce jitter and remove head rotation/translation.

Stage A: Temporal Smoothing of Bounding Boxes

Face detection can "jitter" (bbox shifts slightly between frames). Apply median filter:

smoothed_bbox[i] = median_filter(bbox[i-k:i+k]) for each component (x, y, w, h) kernel_size = 5 (recommended)

Uses scipy.ndimage.median_filter on each bbox component across time. Reduces detection noise while preserving fast changes.

Stage B: Affine Registration to Reference Frame

Even with frame-by-frame alignment, head rotation/translation still appears in standardized frames. Solve this by warping each frame to align its facial keypoints with frame 0's keypoints.

Step 1: Estimate Facial Keypoints

left_eye_point = (x + 0.25w, y + 0.35h) right_eye_point = (x + 0.75w, y + 0.35h) nose_point = (x + 0.50w, y + 0.55h)

Estimate 3 facial keypoints from the bbox (eyes and nose center).

Step 2: Compute Affine Transform

M = cv2.getAffineTransform(current_keypoints, reference_keypoints) where M is a 2×3 affine matrix

For each frame, compute the affine transformation that aligns its keypoints to the reference frame's keypoints.

Step 3: Warp & Crop

warped = cv2.warpAffine(frame, M, (W, H)) crop_region = warped[y_ref:y_ref+side, x_ref:x_ref+side] output = cv2.resize(crop_region, (256, 256))

Apply the affine warp to the entire frame, then crop using the reference frame's crop region. This removes all rigid motion (rotation + translation) relative to frame 0.

Output:

  • std_frames (updated): Registered standardized frames, ready for OF
  • Much cleaner for optical flow: only facial deformation remains, not head motion

Step 5: Apex Detection (Peak Expression Frame)

5Find the Frame of Maximum Expression Intensity

Detect which frame represents the peak ("apex") of the facial expression.

Algorithm: Optical Flow-Based Motion Detection

For each frame i, compute the optical flow from frame 0 (neutral reference) to frame i. The apex is the frame with maximum total motion magnitude.

FOR each frame i in 1..N-1: flow_i = calcOpticalFlowFarneback(gray_frame_0, gray_frame_i) motion[i] = sum of ||flow_i|| per pixel apex_global = argmax(motion[1..N])

Rationale:

  • During expression buildup (onset), pixels move gradually
  • At peak (apex), facial deformation is maximum, so motion is maximum
  • During recovery (offset), motion decreases
  • Thus, argmax(motion) locates the apex

Output:

  • apex_global: Frame index (0-based) in the full video
  • motion: Array of motion magnitudes for all N frames
💡 Tip: Plot motion to visualize the expression arc. You should see a peak near the middle-to-end of the video.

Step 6: Asymmetric Segmentation Around Apex

6Extract Video Segment: Onset → Apex → Offset

Extract a focused window around the apex that captures the full expression arc.

Configuration:

APEX_WINDOW_BEFORE = 40 # frames before apex APEX_WINDOW_AFTER = 5 # frames after apex

Computation:

seg_start = max(0, apex_global - APEX_WINDOW_BEFORE) seg_end = min(N_frames, apex_global + APEX_WINDOW_AFTER + 1) T = seg_end - seg_start # total frames in segment apex_local = apex_global - seg_start # apex index within segment seg_frames = std_frames[seg_start : seg_end]

Interpretation:

  • 40 frames before apex: Captures slow onset (expression buildup)
  • 5 frames after apex: Captures early recovery (decay)
  • Total: ~45 frames at 25 fps ≈ 1.8 seconds
  • Apex appears near the end (frame 40 of 45) → most information is onset/buildup

Output:

  • seg_frames: T standardized frames
  • seg_start, seg_end, apex_local: Metadata for output
  • This segment is the focus for optical flow computation
💡 Asymmetric Window Rationale: Expressions typically have faster onset than offset. By including more frames before apex, we capture the slow buildup phase in detail.

Step 7: Face Masking (Optional)

7Isolate Facial Motion (Optional)

Optionally create a circular mask to isolate optical flow computation to the face region only, excluding shoulders, neck, and background.

Configuration:

USE_FACE_MASK = True FACE_MASK_SIZE = 0.85 # 85% of frame size (0.0-1.0)

Mask Generation:

center = (CROP_SIZE/2, CROP_SIZE/2) radius = (min(CROP_SIZE, CROP_SIZE) / 2) × FACE_MASK_SIZE mask = cv2.circle(zeros(CROP_SIZE, CROP_SIZE), center, radius, 255, -1)

Create a binary circular mask (0 outside, 255 inside) at the center of the 256×256 crop. Radius is FACE_MASK_SIZE fraction of the frame size.

Application to Optical Flow:

gray_masked = cv2.bitwise_and(gray_frame, gray_frame, mask=mask) flow = calcOpticalFlowFarneback(gray_masked_prev, gray_masked_curr, ...)

Apply the mask to grayscale frames before optical flow computation. Masked-out regions become black (0 intensity), so no flow is computed there.

Output:

  • Flow vectors are computed only within the mask region
  • Visualization shows an orange circle marking the mask boundary

Adjustment:

  • FACE_MASK_SIZE = 0.9: Larger, includes more jaw/cheeks
  • FACE_MASK_SIZE = 0.85: Balanced (default)
  • FACE_MASK_SIZE = 0.7: Tight, only central face
💡 Tip: Disable masking (USE_FACE_MASK = False) if you want to see full-frame motion. Use masking to isolate facial deformation.

Step 8: Dense Optical Flow (Farneback Algorithm)

8Compute Dense Optical Flow

Compute dense optical flow on consecutive frames within the segment. Optical flow estimates the motion vector at every pixel.

Algorithm: Farneback

OpenCV's calcOpticalFlowFarneback computes dense optical flow using polynomial expansion approximation (Farneback 2003).

Computation:

FOR each consecutive frame pair (i, i+1) in segment: prev_gray = cvtColor(seg_frames[i], BGR2GRAY) curr_gray = cvtColor(seg_frames[i+1], BGR2GRAY) IF USE_FACE_MASK: prev_gray = bitwise_and(prev_gray, prev_gray, mask=mask) curr_gray = bitwise_and(curr_gray, curr_gray, mask=mask) flow = calcOpticalFlowFarneback( prev_gray, curr_gray, None, pyr_scale=0.5, # pyramid scale levels=3, # pyramid levels winsize=15, # averaging window iterations=3, # iterations per level poly_n=5, # polynomial size poly_sigma=1.2, # Gaussian std flags=0 ) flows.append(flow) # shape (256, 256, 2)

Output Shape:

  • Each flow: (H, W, 2) = (256, 256, 2)
  • flow[y, x, 0] = horizontal motion (dx)
  • flow[y, x, 1] = vertical motion (dy)
  • Total T-1 flow arrays for T-frame segment

Interpretation:

  • Magnitude: √(dx² + dy²) = motion speed (pixels/frame)
  • Direction: atan2(dy, dx) = motion angle
  • Zero flow: Static regions (no motion)
  • Large flow: Fast deformation (mouth, eyebrows, cheeks)
💡 Parameters: These are tuned for 256×256 face crops at 25 fps. Adjust winsize if flow appears too noisy or over-smoothed.

Step 9: Output & Visualization

9Save Data and Create Visualization

Save optical flow data to disk in two formats: (1) compact NPZ for analysis, (2) animated GIF for visual inspection.

Output 1: NPZ File (Compressed NumPy Archive)

np.savez_compressed( "output/optical_flow_npz/DATASET_VIDEONAME.npz", flow = stack(flows), # (T-1, 256, 256, 2) frames = stack(seg_frames), # (T, 256, 256, 3) apex_local = apex_local, apex_global = apex_global, seg_start = seg_start, seg_end = seg_end, fps = fps, motion_all = motion_array, # (N,) face_mask_used = USE_FACE_MASK, face_mask_size = FACE_MASK_SIZE )

Compact binary format, ~5-10 MB per video. Includes all flow data + metadata. Load in Python: data = np.load("file.npz"); flow = data["flow"]

Output 2: GIF Animation (Visualization)

For each flow frame, render a visual representation:

A) Convert Flow to Color (HSV Colour Wheel)

magnitude = sqrt(dx² + dy²) angle = atan2(dy, dx) # -π .. π hue = (angle + π) / (2π) × 179 # direction → hue saturation = 255 # always saturated value = magnitude / max_magnitude × 255 # speed → brightness hsv = stack([hue, saturation, value]) color_map = cvtColor(hsv, HSV2BGR)

Red/yellow: rightward motion. Blue/cyan: leftward motion. Bright: fast motion. Dark: slow motion.

B) Overlay Arrows

FOR each (y, x) in grid(step=ARROW_STEP): dx, dy = flow[y, x, :] end_x = x + dx × ARROW_SCALE end_y = y + dy × ARROW_SCALE cv2.arrowedLine(frame, (x,y), (end_x,end_y), white, thickness=1)

Draw white arrows on a regular grid (spacing = ARROW_STEP pixels) scaled by ARROW_SCALE.

C) Draw Mask Circle (if enabled)

cv2.circle(frame, center=(128,128), radius=int(256/2 × 0.85), color=orange, thickness=2)

Orange circle shows the mask boundary.

D) Annotate Frame

  • Frame counter (bottom-left): global frame index
  • "APEX" label: marks frames near apex
  • "MASK" label: if masking enabled

E) Create GIF

imageio.mimsave( "output/flow_visualization_gif/DATASET_VIDEONAME.gif", gif_frames, fps = fps × GIF_SPEED, loop = 0 # infinite loop )

Export as animated GIF at reduced speed (default GIF_SPEED=0.5). Open in browser or image viewer to inspect flow patterns.

File Naming Convention:

output/optical_flow_npz/ADFES_F01-Joy-Face Forward.npz output/flow_visualization_gif/ADFES_F01-Joy-Face Forward.gif

Format: <DATASET>_<VIDEO_STEM>.<ext>

Configuration Parameters

Parameter Default Range Description
CROP_SIZE 256 128-512 Output face square size (pixels)
PAD_FACTOR 0.35 0.0-0.5 Padding around face bbox. Lower = tighter crop (try 0.2-0.3 if shoulders appear in OF)
APEX_WINDOW_BEFORE 40 10-100 Frames before apex to include in segment
APEX_WINDOW_AFTER 5 0-50 Frames after apex to include in segment
USE_FACE_MASK True True/False Enable circular mask for OF computation
FACE_MASK_SIZE 0.85 0.5-1.0 Mask radius as fraction of frame (0.85 = 85%)
ARROW_STEP 16 8-32 Spacing of arrow grid in GIF (pixels)
ARROW_SCALE 5.0 1.0-10.0 Arrow length multiplier (visual scale)
GIF_SPEED 0.5 0.25-1.0 GIF playback speed (fraction of real speed)
OF_PYR_SCALE 0.5 0.3-0.8 Farneback pyramid scale
OF_LEVELS 3 1-5 Farneback pyramid levels
OF_WINSIZE 15 5-31 Averaging window size (odd). Larger = smoother, slower.
OF_ITERATIONS 3 1-10 Iterations per pyramid level. Higher = more accurate, slower.

Output File Format

NPZ File Structure

Variable Shape Type Description
flow (T-1, 256, 256, 2) float32 Dense optical flow: [dx, dy] per pixel, T-1 frames
frames (T, 256, 256, 3) uint8 Standardized BGR face frames, T frames
apex_local () int32 Apex frame index within segment (0-based)
apex_global () int32 Apex frame index in full video (0-based)
seg_start () int32 Segment start frame index in full video
seg_end () int32 Segment end frame index in full video (exclusive)
fps () float32 Video frames per second
motion_all (N,) float32 Motion magnitude per frame, full video (N frames)
face_mask_used () bool Whether mask was applied to OF
face_mask_size () float32 Mask radius fraction (0.0-1.0)

Loading Data in Python

import numpy as np

# Load file
data = np.load("output/optical_flow_npz/ADFES_F01-Joy-Face Forward.npz")

# Access arrays
flow = data["flow"]                    # (44, 256, 256, 2)
frames = data["frames"]                # (45, 256, 256, 3)
apex_local = int(data["apex_local"])   # e.g., 40
apex_global = int(data["apex_global"]) # e.g., 123
fps = float(data["fps"])               # e.g., 25.0

# Compute flow statistics
u = flow[..., 0]  # horizontal component
v = flow[..., 1]  # vertical component
magnitude = np.sqrt(u**2 + v**2)
angle = np.arctan2(v, u)

print(f"Segment: {len(frames)} frames")
print(f"Max flow: {magnitude.max():.2f} pixels/frame")
print(f"Apex at local frame {apex_local}")

# Plot motion curve
import matplotlib.pyplot as plt
plt.plot(data["motion_all"])
plt.axvline(apex_global, color='r', label='Apex')
plt.xlabel('Frame')
plt.ylabel('Motion Magnitude')
plt.legend()
plt.show()

References

Optical Flow

  • Farneback, G. (2003). "Two-Frame Motion Estimation Based on Polynomial Expansion." SCIA 2003. — Dense optical flow using polynomial approximation.
  • Horn, B. K., & Schunck, B. G. (1981). "Determining Optical Flow." Artificial Intelligence, 17, 185-203. — Foundational optical flow theory.

Face Detection

  • Viola, P., & Jones, M. (2001). "Rapid Object Detection using a Boosted Cascade of Simple Features." CVPR 2001. — Haar cascade detector (used in this pipeline).
  • Lowe, D. G. (2004). "Distinctive Image Features from Scale-Invariant Keypoints." IJCV, 60(2), 91-110. — SIFT (alternative face alignment method).

Facial Expression & Action Units

  • Ekman, P., & Friesen, W. V. (1978). "Manual for the Facial Action Coding System." Consulting Psychologists Press. — Standard facial action units (FACS).
  • Pantic, M., & Bartlett, M. S. (2007). "Machine Analysis of Facial Expressions." in I-Tech Education and Publishing. — Survey of facial expression analysis.

Datasets

  • ADFES (Amsterdam Dynamic Facial Expression Set) — Acted dynamic facial expressions from multiple viewpoints.
  • JeFEE (Japanese Female Facial Expression) — Spontaneous facial expressions from Japanese female actors.
